## 1. Executive summary

M1 delivers a **derive-only** observability contract layer in
`career_intelligence.multi_agent.observability`:

- deterministic per-run and corpus metrics over existing `OrchestrationRun` +
  `Handoff` audits

  no AgentRun store reads inside the module)

presentation, or FR-017 runtime changes. **Horizon 1B remains unblocked.**

BOPA, OBS, Handoff, AgentRun, or orchestration runtime. Derive-only gate **passes**.

## 3. Deterministic metrics contracts

### 3.1 Per-run — `OrchestrationRunMetrics`

Derived from one `OrchestrationRun` plus the handoff records the caller loads
(typically via existing `handoff_ids`). Notable fields:

| Family | Fields (representative) |
|--------|-------------------------|
| Identity / goal | `orchestration_run_id`, `opportunity_id`, `owner_goal_label`, `goal_kind`, flags |
| Outcome | `status`, `stop_reason`, `owner_action_required` |
| Limits | `step_count` / `max_steps`, visit records, `step_limit_reached`, `visit_limit_reached` |
| Handoffs | counts; allow/deny; per-handoff `HandoffMetrics` |
| Observation snapshot | last hash, package/truth/pipeline/readiness class |
| Children | `child_agent_run_ids`, optional `child_agent_metrics`, `ParentChildCorrelation` |
| Optional provider roll-up | `provider`, `model`, tokens, cost, `elapsed_ms` |

### 3.2 Per-handoff — `HandoffMetrics`

Selection reason, policy allow/deny (+ deny reason), acceptance lifecycle,
observed hash, idempotency key, expected output, child refs, optional
`handoff_elapsed_ms` (None when unresolved).

### 3.3 Corpus — `OrchestrationCorpusMetrics`

Aggregates over many `OrchestrationRunMetrics`: run/step/handoff totals, stop
reason histogram, specialist visit totals, optional token/cost/elapsed totals.

### 3.4 API surface (M1)

| Function | Role |
|----------|------|
| `extract_handoff_metrics` | One handoff → `HandoffMetrics` |
| `correlate_parent_child` | Parent/child gap detection |
| `extract_orchestration_run_metrics` | Run + handoffs (+ children) → metrics |
| `aggregate_orchestration_metrics` | Corpus roll-up |
| `evaluate_reconstructability` | R1–R12 report |

## 4. Missing versus zero (normative)

| Field class | Empty audit | Measured zero |
|-------------|-------------|---------------|
| Counts (`handoff_count`, allow/deny, events, steps, …) | **`0`** | `0` |
| Optional provider / model / tokens / cost / latency | **`None`** (absent) | **`0` / `0.0`** means measured zero |

**Never** coerce `None` → `0` for optional provider metadata. Offline / no-child
runs keep token and cost fields `None`. Corpus aggregates keep total token/cost/
elapsed as `None` when no constituent supplied a value.

Unit coverage: `tests/unit/multi_agent/test_observability_m1.py`.

## 5. Parent / child correlation semantics

`ParentChildCorrelation` compares:

- parent `child_agent_run_ids` ↔ handoff `child_agent_run_id`s
- parent `last_brief_id` ↔ handoff `child_brief_id`s
- handoff `orchestration_run_id` must match parent

Orphans are listed explicitly (`orphan_parent_*`, `orphan_handoff_*`,
`orphan_handoff_brief_ids`). `correlation_complete` is true only when there are
no orphans and all handoffs cite the parent run id.

R11 consumes this structure.

## 6. R1–R12 reconstructability contracts

Implemented as `evaluate_reconstructability` → `ReconstructabilityReport`.

| Id | Question (summary) | Evidence used |
|----|--------------------|---------------|
| R1 | Owner goal | `OrchestrationGoal` |
| R2 | Authoritative observation | `last_observation` (+ hash) |
| R3 | Specialist selection / why | allow handoffs, deny handoffs, or selection events |
| R4 | DelegationPolicy allow/deny | handoff `policy_*` consistency |
| R5 | Specialist authority boundary | target ∈ {`obs`,`bopa`} |
| R6 | Handoff lifecycle | `acceptance` present |
| R7 | Child AgentRun / brief | completed allow handoffs cite expected child refs (stopped may omit) |
| R8 | Stop reason | required when not `running` |
| R9 | Owner next step | required when `awaiting_owner` |
| R10 | Step / visit limits | limits visible; flags report proximity/hit |
| R11 | Parent → handoff → child walk | `ParentChildCorrelation` (vacuous OK if no children/handoffs) |
| R12 | Resume / idempotency evidence | observation hashes and/or idempotency keys (early running with no handoffs vacuous) |

**Documented early-run limitation:** A brand-new `running` run with no handoffs and
no selection events may fail R3 until selection evidence exists. That is honest
reconstructability, not a runtime defect. Corpus demonstration of R1–R12 across
FR-016 cases A–T is **M2**.

Optional `prior_observation_hash` strengthens R12 when comparing resume
observations.
