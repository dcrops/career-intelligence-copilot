## 2. CLI design

| Command | Purpose |
|---------|---------|
| `cic agent orchestrate metrics <orr_…>` | Evaluate one persisted orchestration run |
| `cic agent orchestrate metrics --fixture <CASE>` | Evaluate static demo fixture (no store I/O) |
| `cic agent orchestrate metrics --list-fixtures` | List demo fixture ids |
| `cic agent orchestrate metrics-corpus` | Run deterministic acceptance corpus + aggregates |

Optional: `--orchestration-runs-dir`, `--agent-runs-dir`, `--prior-hash` (R12).

Child `AgentRunMetrics` are loaded read-only when agent-run files exist; otherwise
token/cost fields stay **missing** (C09 semantics).

---

## 3. Presentation format

ASCII report sections:

1. Header (FR-017 derive-only; prefer `cic agent run`)
2. Identity / owner goal / status / stop / owner next action / limits
3. Observed state
4. Selection / specialist visits
5. Handoffs (delegation, lifecycle, children, idempotency)
6. Parent/child correlation + **ORPHAN** lines
7. Optional provider/token/cost with **missing** vs **0**
8. Resume / idempotency evidence
9. R1-R12 PASS/FAIL with details
10. Safety footer (read-only; 1B not gated)

Corpus report: per-case PASS/FAIL, go/no-go, aggregate metrics.

---

## 4. Reconstruction behaviour

Parent → handoff → child → stop is walked from derived metrics:

- selected specialists and selection reasons
- allow/deny + deny reason
- acceptance lifecycle
- `child_agent_run` / `child_brief`
- stop reason + owner next action (FR-016 mapping when store-backed)
- step/visit limits and flags
- observation hashes + idempotency keys

---

## 5. R1-R12 display

Each criterion printed as `Rn PASS|FAIL:` with question and detail. Summary
`satisfied=k/12 all_satisfied=…`.

## 6. Missing-data semantics

| Display | Meaning |
|---------|---------|
| `missing` | Field absent (`None`) |
| `0` / `0.0` | Measured zero |
| WARNING | Child ids present but token/cost join missing |
| NOTE | Measured zero present (distinct from missing) |
